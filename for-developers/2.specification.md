# specification

## 1. 概要

架空の「カンバン式タスク管理ダッシュボード」のUIモックを、Before / After の2版で作成する。
想定ユーザーはチームリーダー(TL)であり、自分自身ではなくチーム全メンバーのタスクを一元管理することがこのダッシュボードの責務とする。
ゴールは `goal_for_this_project.md` を参照。

## 2. 技術方針

- Vue 3 + Element Plus。いずれも CDN(ESMビルド)を `<script type="module">` で読み込む
- JavaScript(TypeScriptは使用しない)
- ビルドツールは使用しない。`index.html` を Live Server で直接表示する想定
- データはメモリ上のみ(永続化しない)
- バックエンド、API通信は持たない
- ダミーデータや集計・フィルタ・ソートなどのビジネスロジックは Before / After で共有する(`shared/` 配下を参照)。Before / After の差分は主に HTML・CSS で表現し、After 側で挙動が異なる操作(ドラッグ&ドロップ、レーンのタブ切替えなど)がある場合のみ追加の JS ファイルを設ける

### 2.1 ディレクトリ構成

Before(オリジナル) / After(改善後)を別ディレクトリに分け、それぞれ自己完結した `index.html` を持つ。ダミーデータと共通ロジックは `shared/` に置き、両ディレクトリから相対パスで読み込む。

```
mocks-for-uiux-improvement/
├ shared/
│  ├ data.js    … ダミーデータ(メンバー・タスク・通知)
│  └ logic.js   … 共有ビジネスロジック(集計・フィルタ・ソートなどの純粋関数)
├ original/   … Before。素朴な実装。AIが直接生成したものをそのまま採用する(人手による作り込みは行わない)
│  ├ index.html
│  └ style.css
└ improved/   … After。設計判断を適用したもの
   ├ index.html
   ├ style.css
   └ app.js    … After固有のインタラクション(ドラッグ&ドロップ、レーンのタブ切替え等)を追加する場合に使用
```

- Before / After の切り替えはタブやアプリ内の切替ではなく、ディレクトリを別々にLive Serverで開く方式とする。

## 3. 画面構成

```
[PC]
┌───────────────────────────────────────────┐
│ サイドバー(ナビゲーションのみ、画面左に固定・開閉可)                 │
├───────────────────────────────────────────┤
│ ヘッダ(アプリ名・アイコン / サイドバー開閉トグル / 画面タイトル / 通知(未読件数) / ログインユーザー情報 / 状態表示 / 主要操作) │
├───────────────────────────────────────────┤
│ サマリ部(レーン別・メンバー別件数・期限超過件数などのKPI表示) │
│ 通知部(自動レポート・メンバーからのメッセージ・期限超過アラートの一覧) │
│ フィルタ・検索部(メンバー・ラベル・期限などの絞り込み) │
│ ボード部(可変長のカンバンレーン、チーム全メンバーのカードの集合) │
└───────────────────────────────────────────┘

[モバイル](サイドバーなし)
┌ ヘッダ(画面タイトル / 通知 / ログインユーザーアイコン / 状態表示)
├ サマリ部
├ 通知部
├ フィルタ・検索部
└ ボード部(タブ/セレクトでレーン切替え)
```

サイドバーは PC 版のみ、画面左に固定表示し、ナビゲーション項目のみを置く(アプリ名・アイコン、ログインユーザー情報、開閉トグルはヘッダ側に配置する)。モバイル版はサイドバーを持たず、ログインユーザー情報はヘッダ内のアイコンとしてのみ表示する。

### 3.1 サイドバー(PC版のみ)

サイドバーのナビゲーションは、(仮想的に存在する)アプリ内のどのページでも共通で表示されるグローバルな遷移先一覧とする。そのうち本モックが実装するのは「ボード」(本画面)のみであり、他は非遷移の飾り項目とする(非ゴール: 複数画面遷移なしのため)。通知のように本画面内に常時表示されるセクションは、別画面ではないため遷移先一覧には含めない。

| 項目 | 種別 | 備考 |
|---|---|---|
| ナビゲーション項目 | ボタン(装飾) | 「ボード」のみ活性表示。他(例: メンバー、レポート、設定)はクリックしても遷移しない飾り項目(非ゴール: 複数画面遷移なしのため) |

### 3.2 ヘッダ

| 項目 | 種別 | 備考 |
|---|---|---|
| アプリ名・アイコン | 表示(ロゴ+テキスト、仮) | 固定表示 |
| サイドバー開閉トグル | ボタン | サイドバーの表示/非表示(開閉)を切り替える(PC版のみ) |
| ボード名 | テキスト(固定値) | 編集不可 |
| 通知ベル | アイコン+未読件数バッジ | 未読件数のインジケータ。通知部(3.3)は画面内に常時表示するため、クリックしても非表示にはせず、通知部へスクロールする程度の挙動とする |
| ログインユーザー情報 | アバター+名前+設定アイコン(PC) / アバターのみ(モバイル) | クリックでダミーの設定メニュー(飾り)を開閉 |

### 3.3 通知部

通知の種別(3種類):

- 自動作成のレポート(例: 定時で自動生成される「本日の完了タスク数」「レーン別件数」などのサマリ。日付・時刻付き)
- ダミーユーザーからのメッセージ(タスクへのコメントを想定したダミー文面)
- タスク期限超過アラート(期限を過ぎたカードを検知して自動発行)

通知の項目:

| 項目 | 種別 | 備考 |
|---|---|---|
| 通知種別 | アイコン+ラベル | レポート / メッセージ / 期限超過アラート |
| 発生日時 | 日時 | 新しい順に並べる |
| 発信者 | アバター+名前 | レポート・アラートはシステム発信として表示 |
| 内容 | テキスト | メッセージは本文、レポートはサマリ文言、アラートは対象タスク名を含む |
| 既読/未読 | 状態 | 未読は強調表示 |
| 関連カードへのリンク | ボタン/リンク | 期限超過アラートや一部のメッセージから該当カードへジャンプ |

- 初期表示は合計10〜15件程度のダミー通知とし、既読・未読を混在させる。

### 3.4 フィルタ部

| 項目 | 種別 | 備考 |
|---|---|---|
| 表示メンバー | セレクト(複数選択) | 既定でチーム全メンバー(ダミー5名程度)を表示、個人単位の絞り込みも可能 |
| 期限フィルタ | 日付範囲 | 期限での絞り込み |
| ラベルフィルタ | セレクト(複数選択) | ダミータグ |
| 検索 | テキスト | タスク名でのインクリメンタル検索 |
| 並び順 | セレクト | 期限順 / 優先度順 / 作成日順 |

### 3.5 ボード部(カンバンレーン)

レーン構成: 未着手 / 対応中 / レビュー中 / 完了 の4レーン。

カードの項目:

| 項目 | 種別 | 備考 |
|---|---|---|
| タスク名 | テキスト | |
| 担当者 | アバター表示 | ダミー5名 |
| 期限 | 日付 | 超過時は強調表示 |
| 優先度 | タグ(高/中/低) | 色分け |
| ラベル | タグ(複数) | 種別分類用ダミー |
| 進捗メモ | テキスト(省略表示) | 長文は折りたたみ等で対応 |
| 操作 | ボタン | 編集 / 削除 / レーン移動 |

- 初期表示は合計20〜30枚程度のダミーカードをチーム全メンバー分4レーンに分散。
- 1レーンあたり0〜15枚程度を想定する(スクロールが発生する量を含める)。

### 3.6 サマリ部

- レーン別件数、期限超過件数、担当者(メンバー)別件数などをKPI表示する。
- 集計は件数カウントのみとし、金額計算などのビジネスロジックは持たない。

## 4. 機能範囲

ビジネスロジックを含まない、UI操作としての機能のみ実装する。静止画像ではなく、以下は実際に動作するインタラクションとして実装する。

- カードの追加、削除、複製、レーン間移動(ドラッグ&ドロップまたはボタン操作)
- レーン内での並べ替え
- 担当者・ラベル・期限によるフィルタ、検索、並び順の変更は実際に一覧が絞り込まれ・並び替わるようにする
- ツールチップやダイアログ(モーダル等)がある番側は、実際に開閉できるようにする
- 必須項目の未入力などを示す入力エラー表示(ルールは形式チェックのみ)
- 保存操作(実際には保存せず、状態表示のみ更新)
- 未保存変更の表示
- 通知一覧の表示、既読/未読の切り替え、通知から関連カードへのジャンプ

## 5. Before / After の差分方針

Before は「素朴な実装」、After は各観点に設計判断を適用したものとする。
Before は、AI が仕様(本ドキュメント)から直接生成したものをそのまま採用する。意図的な作り込みや劣化は行わない。
下表は**設計意図の仮置き**であり、実装後に実際の差を確認して更新する。

| 観点 | Before(素朴な実装) | After(設計判断の方向性) |
|---|---|---|
| カードの編集方法 | 別ダイアログを開かないと編集できず、項目が常時密集 | インライン編集やクイック操作で最小手数化 |
| カードの移動 | セレクトでのステータス変更のみ | ドラッグ&ドロップやキーボードでも移動可 |
| カード追加位置 | ボード上部にのみ追加ボタン | レーンごと・カード間に追加導線を配置 |
| エラー表示 | 保存時にまとめて上部表示 | 該当カード近傍に表示、件数と該当カードへのジャンプを提示 |
| サマリ(件数)表示 | ボード下部でスクロールしないと見えない | 画面上部に固定表示 |
| 通知の提示方法 | 種別を問わず全件がフラットなリストで並び、未読が埋もれる | 種別アイコン・未読強調・未読件数バッジで気づきやすくし、関連カードへ直接ジャンプ |
| モバイル幅でのレーン表示 | PCと同じ操作感を維持(4レーンを横並びのまま、横スクロールで閲覧) | タブ/セレクトでレーンを切り替え、一度に1レーンのみ表示 |
| 情報の優先度 | カード内の全情報が同じ重みで表示 | 期限・優先度を強調、補足情報は折りたたみ |
| 操作ボタン | カードごとに複数ボタンが常時並ぶ | 頻度の低い操作をメニューに集約 |
| 未保存状態 | 表示なし | ヘッダに状態表示、離脱時に確認 |

## 6. 非機能要件(モックとしての最低限)

- 対応ブラウザ: 最新版のデスクトップ向けブラウザ(Chrome / Edge)
- 画面幅: 1280px 以上を主対象とし、PC / モバイルは CSS の `@media` で切り替える(実装上、モバイル用に別の index.html を用意する形でもよい)
  - Before(original): モバイル幅でも PC と同じ操作感を維持する(4レーンを横並びのまま横スクロールさせるだけで、レーン切替えUIは導入しない)
  - After(improved): タブ/セレクトでレーンを切り替え、一度に1レーンのみ表示する(設計判断の一つとして導入)
- 表示密度(コンパクト / 標準)の切り替えは行わない(標準表示のみ)
- ダークテーマは切り替え可能にする
- Before / After で、データ・部品・配色の基本設定は揃える(差分をUI設計判断に限定するため)

## 7. ダミーデータ

- メンバー名、タスク名などはすべて架空とする。実在の企業名・人名・社内データは使用しない。
- 優先度・期限はバラつきを持たせ、期限超過の強調表示やタグの色分けの効果が確認できるようにする。
- 通知のレポート文言・メッセージ本文も架空とし、発信者名はダミーとする。
